# INDEX — SEO Command Center

INDEX is a multi-site SEO operations workspace for monitoring websites, reviewing measured search signals, generating approval-gated improvement proposals, and preparing content changes before publishing.

## Current production architecture

- **Web app:** Next.js on Railway
- **Database/Auth:** Supabase
- **Workspace isolation:** PostgreSQL RLS
- **Production branch:** `feat/index-foundation`
- **Production URL:** `https://index-web-production-2e5b.up.railway.app`

## Core workflow

1. Monitor website portfolio and measured performance.
2. Analyze real Search Console metrics when the GSC connector is available.
3. Create proposals with evidence attached.
4. Workspace owner approves or rejects each proposal.
5. Approved proposals can become drafts.
6. Publishing remains locked until a website publisher connector is explicitly configured.
7. Published changes can later be evaluated against subsequent measured performance.

INDEX does not fabricate Google metrics and does not publish automatically when a required provider is disconnected.

## Proposal safety gates

- Editors can submit manual proposals.
- Only owners can approve or reject proposals.
- Manual proposals cannot claim `measured_gsc` provenance.
- Measured proposals are generated by a database-side deterministic engine from `site_metrics_daily` rows whose source is `gsc`.
- Duplicate measured proposals are prevented with weekly fingerprints.
- A proposal must be approved before it can create a linked draft.
- One proposal can create at most one linked draft.

## Measured analysis rules

The first analysis engine compares the latest 14 days with the preceding 14 days and can surface:

- meaningful average-position decline,
- low CTR at useful ranking positions and sufficient impression volume,
- substantial organic click decline.

Each proposal stores the exact measured evidence used by the rule. If Search Console is not connected or no measured GSC rows exist, analysis returns a blocked status and creates nothing.
